# notes.md — Conexión OpenClaw: Telegram, Zapier MCP, Google Docs y Calendar

- Bot de Telegram creado con BotFather (@KaiOpenClawJheremyBot), token guardado en `openclaw.json` bajo `channels.telegram.botToken`.
- Se habilitó `dmPolicy: "pairing"` para que solo mi cuenta de Telegram pueda hablarle al agente tras aprobar el emparejamiento con `openclaw pairing approve telegram <CODE>`.
- Al editar `openclaw.json` a mano cometí un error de sintaxis (coma y llave de cierre faltantes al insertar el bloque `channels`); lo detecté validando con `python3 -m json.tool` antes de reiniciar el gateway, para evitar levantar un servicio con config rota.
- Para Zapier MCP se usó el flujo guiado: se pegó el prompt de conexión de Zapier directamente en el chat de Telegram con el agente, que instaló `mcporter`, generó el link de autorización OAuth y completó el emparejamiento pegando de vuelta la URL de callback (el callback a `127.0.0.1:<puerto>` da "conexión rechazada" en el navegador — es esperado, ya que el servidor temporal corre en el VPS, no en la máquina local).
- Se usó una cuenta de Gmail dedicada de prueba (no la cuenta personal/de trabajo) para autorizar Google Docs y Google Calendar, como pide el enunciado.
- Problema encontrado: el primer intento de crear un documento en Google Docs falló con "Insufficient Permission" porque la autorización inicial no incluía los scopes de escritura completos. Se resolvió reconectando Google Docs desde el link que el propio agente volvió a generar, aceptando todos los permisos (ver/editar/crear/eliminar documentos).
- Verificación del flujo completo por Telegram: se pidió crear un documento ("Plan de Estudio OpenClaw") y luego un evento de calendario vinculado a su revisión; el agente confirmó ambas acciones con enlaces directos a los recursos creados.
- Verificación adicional vía panel de Zapier (pestaña History): se confirmaron las llamadas reales al MCP — "Google Docs: Create Document From Text" (Success, tras el Failed inicial por permisos) y "Google Calendar: Create Detailed Event" (Success) — demostrando que las acciones del agente efectivamente se enrutaron a través del servidor MCP y no fueron simuladas.
- No se expusieron tokens, API keys ni credenciales en las capturas entregadas; el token de Telegram y los Connection IDs de Zapier se recortaron o se evitó incluirlos en las imágenes finales.
